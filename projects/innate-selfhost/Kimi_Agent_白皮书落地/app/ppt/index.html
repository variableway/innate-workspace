WEIGHT FLIP · 两个翻转场景

换一次权重,第一名易主

01便利性加权至 40%
Supabase 托管反超第一

加权分约 3.9,反超组合栈(3.6)与 InsForge(3.5)。这也是市场上 Supabase 仍是基准的现实原因——多数团队的贴现率就是很高。

  • 结论翻转:初创 / MVP 直接上托管
  • 别为理论上的可迁移性付工程税
  • 临界点:维度①权重 > 30% 时托管版胜出
02不锁定 + 私有云 ≥ 35%
组合栈断层领先

加权分升至约 4.6,与第二名 InsForge(3.9)拉开断层;Supabase 托管跌至倒数第二(约 2.9)。胜出且不可撼动。

  • 数据主权 / 合规审查 / 私有云交付场景
  • 一体化平台全部让位
  • Nubase 在任何合理权重下都不进前三

01
Supabase 仍是基准,但正被两面夹击

向上:20+ 计量项(磁盘 $0.125/GB、出口 $0.09/GB、PITR $100/月)成本随规模线性恶化;向下:PG17 镜像弃用 TimescaleDB——"用的是真 PG"与"PG 归你管"是两回事。

02
2026 年的分化轴是"Agent 操作面"

功能面高度同质化后,谁把后端变成 AI 编码代理可直接操作的对象谁赢:InsForge 的 MCP / CLI JSON / backend branching / diagnose 是当前最完整的 agent DX。

03
"一个库干五件事"在中等规模成立

pgvector + pg_search 0.25.2 + TimescaleDB 2.29.1 + pgai + DuckDB,让五类负载在 TB 内收敛到一个 PG 底座;代价是 AGPL 与 TSL 两条法务硬约束。

ONE DATABASE · FIVE WORKLOADS

一个库,干五件事

CORE · 内核

PostgreSQL 系统记录:OLTP、事务、RLS、WAL 审计链——一切负载的锚点。

MIDDLE · 扩展层

pgvector(向量)+ pg_search(BM25 混合)+ TimescaleDB(时序/连续聚合)+ pgai(自动 embedding 管道)。

OUTER · 互补层

DuckDB 嵌入式 OLAP 即席卸载;ClickHouse 仅在 TB 级/亚秒聚合 SLA 命中时接入,PG 不退场。

约束:pg_search 为 AGPL-3.0、TimescaleDB 高级功能属 TSL;托管政策风险现实存在(Neon 已禁用 pg_search,RDS 不支持)。

Risk Register · 精选四条
14 / 20
R1 / R3 / R9 / R10 · 采用前必须处置

风险登记册

R1
InsForge 密钥回退链 · 高

ENCRYPTION_KEY 未设置时静默回退用 JWT_SECRET 加密全部 secrets(#905 已确认,#1552 加固仍 open);轮转即永久不可读。缓解:显式独立密钥,升级前核对 compose 回退链。

R3
Nubase 稚嫩且信号异常 · 高

v0.1.4、开源两个月、620 stars 对 0 issues。缓解:不作生产采用,仅技术观察;试用须隔离网络、不放真实数据。

R9
pg_search AGPL-3.0 · 高(商用)

网络服务场景触发开源义务,AWS RDS 不支持、Neon 已禁用。缓解:法务书面确认,或换 tsvector/lakebase 系方案。

R10
TimescaleDB TSL 双轨 · 中

连续聚合/列压/保留策略属 TSL:自用免费,禁止作为托管 DBaaS 转售;2.29.0 起移除 PG15。缓解:逐功能核对归属,可用 oss 标签镜像规避。
