# Plan: innate-selfhost 仓库结构规划

## Context

`innate-selfhost` 是一个管理本地/私有云环境搭建的仓库。当前仓库内有三个独立的调研/实现目录（`Kimi_Agent_*`），包含 AI Agent Runtime 调研报告、OPC Hub 部署页面、白皮书工程实现（memweave + baas/lazycat）和 PG 后端选型交互式报告。用户希望在保留现有内容的基础上，新建一套标准化的仓库目录结构，支持懒猫私有云部署，并为未来扩展（AI Agent Runtime、自托管 BaaS、本地 LLM、开发工具链）预留空间。

## 设计原则

1. **服务即目录** — 每个可部署服务一个独立目录，含自己的 `docker-compose.yml` 和 `README.md`
2. **共享基础设施提取** — 网络、存储、监控等横切关注点放入 `infra/`
3. **脚本分层** — `scripts/` 放通用工具，各服务内放专属脚本
4. **文档即代码** — 每个服务和模块都有 README，根目录有总览
5. **渐进式扩展** — 先跑通懒猫，后续按相同模式添加服务

## 实施步骤

### Step 1: 创建骨架目录和基础文件
- 创建 `infra/`, `services/`, `scripts/`, `docs/` 目录
- 创建 `.gitignore`（Docker volumes、Python __pycache__、.env、node_modules 等）
- 创建 `LICENSE`

### Step 2: 编写根 README.md
- 项目定位与用途
- 目录结构地图
- 快速开始（3 步：clone → 配置 → 部署）
- 服务矩阵表格（名称 | 状态 | 说明 | 端口）

### Step 3: 迁移已有服务到 services/
- 从 `Kimi_Agent_白皮书落地/ai-memory-backend/baas/` 复制到 `services/baas/`
- 从 `Kimi_Agent_白皮书落地/ai-memory-backend/memweave/` 复制到 `services/memweave/`
- 更新各服务 README 中的路径引用

### Step 4: 创建 infra/ 共享基础设施
- `docker-compose.base.yml`：定义 `selfhost-net` 网络
- `env.example`：全局环境变量模板（域名、时区、数据目录）

### Step 5: 编写 scripts/ 运维脚本
- `setup.sh`：检查 docker/docker-compose 是否安装，创建 .env，创建外部网络
- `deploy.sh`：接收服务名参数，调用对应 `docker compose up -d`
- `backup.sh`：PG dump + tar 打包 volumes
- `health-check.sh`：curl 探活各服务端口

### Step 6: 编写 docs/ 文档
- `architecture.md`：架构图（ASCII art）、组件关系、数据流
- `lazycat-deployment.md`：懒猫部署完整指南（从安装 lzc-cli 到 app install）
- `network.md`：端口分配表、Traefik 路由规则

### Step 7: 创建预留服务目录
- `services/ollama/`：docker-compose.yml + README
- `services/agent-runtime/`：README 占位
- `services/devtools/`：README 占位

## 验证方式

1. `tree -L 2` 确认目录结构正确
2. `cd services/baas && docker compose config -q` 验证 compose 文件语法
3. `cd services/baas/lazycat && bash deploy.sh --build` 验证 LPK 打包（需 lzc-cli）
4. `bash scripts/setup.sh` 验证环境初始化脚本
5. `bash scripts/health-check.sh` 验证健康检查脚本
6. 各 README.md 中的命令可复制执行
