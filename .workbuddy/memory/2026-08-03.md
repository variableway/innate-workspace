## Agent Kanban 双后端实现计划

用户要求后端用 Go 和 Node.js 同时实现。重新设计了实现计划，取代之前的单后端方案。

核心架构：OpenAPI 是唯一契约，两个后端各自实现，前端通过 BACKEND_URL 切换。

三层共享：
- spec/openapi.yaml (canonical API 契约)
- spec/schema.sql (canonical DB schema)
- spec/types.ts (从 OpenAPI 生成)

Go 后端技术栈：chi v5 + sqlx + modernc.org/sqlite (纯 Go) + go-github + golang-migrate + slog
Node.js 后端技术栈：Hono + better-sqlite3 + octokit + zod + vitest

关键决策：
- Go 用 chi 而非 Gin（标准库兼容）
- Go 用 modernc.org/sqlite 而非 mattn（无需 CGO）
- Node.js 用 Hono 而非 Express（TS 原生）
- Node.js 用 better-sqlite3 而非 Prisma（与 Go 的 database/sql 对称，便于对比）
- 共享 SQLite 文件（MVP 阶段）
- 契约测试驱动（两个后端必须通过同一套测试）

分 7 个 Phase：
- Phase 0: 共享契约层 (1 天)
- Phase 1: Go 后端 MVP (3 天，与 Phase 2 并行)
- Phase 2: Node.js 后端 MVP (3 天，与 Phase 1 并行)
- Phase 3: GitHub 同步双后端 (2 天)
- Phase 4: 看板 UI (3 天，复用 innate-fe-base)
- Phase 5: Label Router 双后端 (2 天)
- Phase 6: 对比测试 + 部署 (1 天)
- 合计 8-9 天（因 Phase 1/2 并行，比单后端 9-11 天更短）
- MVP (Phase 0 + 1 或 2 + 4) = 5 天

输出文档：`projects/agent-kanban/suggestion/07-dual-backend-implementation-plan.md`

## Phase 0 执行：共享契约层

执行了双后端计划的 Phase 0，在 `projects/agent-kanban/docs/` 下创建了 8 个 canonical 契约文件：

1. **docs/schema.sql** — canonical DB schema，7 张表 (kanban_workspace/project/task/agent/assignment/audit_log/webhook_subscription) + 9 个索引。用 `kanban_` 前缀避免与 better-auth 表冲突。
2. **docs/openapi.yaml** — 增强版 API 契约 (v1.1.0)，含所有请求/响应 examples、securitySchemes、统一错误响应、新增 `POST /assignments/auto` 端点。
3. **docs/types.ts** — 手写 TS 类型定义，对齐 schema.sql 表结构。
4. **docs/events.yaml** — 事件契约：7 个 GitHub webhook 事件 + 8 个内部模块间事件 + 2 个 outbound webhook 事件。
5. **docs/contract-tests.yaml** — 25 个契约测试用例，两个后端必须全通过。
6. **docs/states/task-states.yaml** — Task 状态机 (open→in_progress→closed + reopen)。
7. **docs/states/assignment-states.yaml** — Assignment 状态机 (pending→running→done/failed)，含重试和超时。
8. **docs/README.md** — 目录说明，含 Go/Node/前端各自的使用方式和修改规则。
