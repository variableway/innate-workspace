## AgentTODO 参考项目分析

Clone 了 https://github.com/alanhsun/AgentTODO.git 到 `projects/agent-kanban/references/AgentTODO/`，分析可借鉴的设计模式。

AgentTODO 是单用户、本地化、为 AI 助手设计的任务管理中枢。虽然是单项目模型，但接入层设计成熟。

8 个值得借鉴的设计：
1. **CLI Skill System (BaseSkill + SkillManager)** — 可热加载的 skill 架构，通过 require.cache 清除实现 reload
2. **HTML 注释式元数据标记** — `<!-- @purpose -->`, `<!-- @input -->`, `<!-- @output -->` 比 YAML front-matter 更轻量，能标记文件内段落
3. **三层 AI 接入** — REST API + CLI Skill + Python Wrapper，覆盖不同 AI 客户端
4. **AI 工作流提示词模板** — 把"AI 何时调用哪个技能"作为产品一部分交付
5. **Webhook 主动推送** — webhookService + node-cron，事件驱动
6. **渐进式 Migration** — 按主题拆分 SQL migration 文件
7. **Skill 代码的"为什么"注释** — 中文注释解释设计决策，对 AI 阅读友好
8. **Zero-Auth 作为部署选项** — 本地可信网络零配置

不建议借鉴：单用户数据模型、无 OpenAPI examples、Webhook 无签名验证、CLI 用空格分割而非 JSON-RPC。

输出文档：`projects/agent-kanban/suggestion/04-agenttodo-reference-analysis.md`

## LobsterBoard 参考项目分析

Clone 了 https://github.com/Curbob/LobsterBoard.git 到 `projects/agent-kanban/references/LobsterBoard/`。

LobsterBoard 是自托管拖拽式 Dashboard Builder，60+ widgets，与 AgentTODO 完全不同——它是"系统扩展性设计"的典范。

10 个值得借鉴的设计：
1. **Widget Registry Pattern** ⭐⭐⭐ — 全局 WIDGETS 对象 + 按类别分文件，每个 widget 是标准对象（name/icon/category/properties/generateHtml/generateJs）
2. **Community Widget Template** ⭐⭐⭐ — `community-widgets/_template/` 提供完整带注释的模板，copy-paste 即可贡献
3. **Auto-discovered Pages** ⭐⭐⭐ — `pages/` 下每个文件夹是一个页面，drop folder + restart = 新页面出现
4. **Page API 微框架** ⭐⭐⭐ — `api.cjs` 导出函数返回 routes 对象，格式 `'GET /:id': (req,res,{params}) => {...}`，返回值自动 JSON 序列化
5. **Template Gallery** ⭐⭐⭐ — dashboard 布局 export/import/分享，支持 merge/replace 两种导入模式
6. **DEVJARVIS_WORKFLOW.md** ⭐⭐⭐ — AI Agent 作为正式贡献者的工作流规范，含 Pre-PR Checklist（testing/security/usefulness）
7. **Config-driven Property Panel** ⭐⭐ — properties 对象自动生成编辑表单，类型从默认值推断
8. **SSE 实时推送** ⭐⭐ — `/api/stats/stream` 用 Server-Sent Events，比轮询更实时
9. **Theme Variables** ⭐⭐ — CSS 变量统一管理，5 个主题切换变量值
10. **Remote Agent 分发** ⭐ — `lobsterboard-agent` 独立 npm 包，中心 dashboard + 分布式 agent

不建议借鉴：BSL-1.1 许可证、单文件 server.cjs、无构建步骤、generateJs 用 new Function()（安全隐患）。

两个参考项目互补：AgentTODO 教"AI 接入层"，LobsterBoard 教"系统扩展性"。

输出文档：`projects/agent-kanban/suggestion/05-lobsterboard-reference-analysis.md`

## 基于 innate-fe-base 的 Agent Kanban 实现计划

分析了 `/Users/patrick/innate/innate-works/base/innate-fe-base` 项目，发现它几乎是为 agent-kanban 量身定制的底座——80% 的基础设施已存在。

innate-fe-base 是 pnpm monorepo（Next.js 16 + TypeScript + Tailwind 4 + Prisma + SQLite），已有：
- @innate/ui (60+ shadcn 组件)、@dnd-kit (拖拽)、better-auth (认证)、next-themes (主题)
- AGENTS.md (AI 入口文件)、scene-specs L3 规范系统、skills-kit 技能系统
- Prisma + SQLite、@tanstack/react-table、recharts

推荐方案：在 `apps/admin-nextjs` 中新增 `/dashboard/kanban/*` 路由（方案 A），零配置复用全部基础设施。

需要新增的内容：
1. Prisma schema 追加 5 个模型 (Workspace/Project/Task/Agent/Assignment)
2. API 路由 (workspaces/projects/tasks/agents/assignments/webhooks)
3. 看板页面 + 组件 (kanban-board/task-card/stats-bar/filter-bar)
4. GitHub 同步引擎 (webhook receiver + octokit + 验签)
5. Label Router (标签匹配引擎)
6. 仅需新增 1 个依赖：octokit

分 5 个 Phase 实施：
- Phase 0: 环境准备 (0.5 天)
- Phase 1: 数据模型 + API (2 天)
- Phase 2: GitHub 同步 (2 天)
- Phase 3: 看板 UI (3 天)
- Phase 4: Agent 管理 + 分配 (2 天)
- Phase 5: Agent 执行集成 (可选, 2 天)
- MVP (Phase 0-3) = 5.5 天

关键决策：在 admin-nextjs 加路由而非新建 app；用 Prisma 替代裸 SQL；Label Router 用应用层匹配；Agent 执行放在 WorkBuddy 侧。
